# Intelligent Cloud FinOps Platform

Cloud cost management and optimisation platform built with **Floci** (local AWS emulator),
**Python / boto3**, and **Streamlit**.

This version implements **Modules 1–5** of the term project:

| # | Module | Page | Core code |
|---|--------|------|-----------|
| 1 | Cloud Service Pricing Explorer | `pages/1_Pricing_Explorer.py` | `finops/pricing.py` |
| 2 | Cloud Cost Explorer | `pages/2_Cost_Explorer.py` | `finops/billing.py` |
| 3 | Infrastructure Configuration Builder | `pages/3_Infrastructure_Builder.py` | `finops/config_store.py` |
| 4 | Infrastructure Cost Estimator | `pages/4_Cost_Estimator.py` | `finops/estimator.py` |
| 5 | Pricing Model Comparison | `pages/5_Pricing_Comparison.py` | `finops/pricing_models.py` |

The Home page (`app.py`) shows an overall cost summary against the $5,000 monthly budget and
the Floci compatibility check.

## Setup

### 1. Start Floci

Requires Docker Desktop.

```bash
docker compose up -d          # starts floci/floci:latest-compat on http://localhost:4566
docker compose ps
```

`docker-compose.yml` runs Floci with persistent storage in `./floci-data` (git-ignored).
Only one Floci container can use port 4566 at a time, so stop any other Floci container first.

### 2. Python environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Check which Floci operations work

```bash
python -m finops.capabilities
```

### 4. Run the dashboard

```bash
streamlit run app.py
```

Open http://localhost:8501.

### 5. Run the tests

```bash
python -m pytest -q
```

The tests do not need Floci to be running.

### Configuration

| Variable | Default | Purpose |
|----------|---------|---------|
| `FLOCI_ENDPOINT` | `http://localhost:4566` | Floci endpoint used by every boto3 client |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | `test` / `test` | Dummy credentials (Floci accepts any) |
| `AWS_DEFAULT_REGION` | `us-east-1` | Default client region |

## Floci compatibility findings

Results of `python -m finops.capabilities` against `floci/floci:latest-compat`:

| Service | Operation | Result |
|---------|-----------|--------|
| Pricing | `describe_services` | Supported. Only **AmazonEC2, AmazonS3, AWSLambda** |
| Pricing | `get_attribute_values` | Supported (8 EC2 instance types, 5 locations) |
| Pricing | `get_products` | Supported, but only **5 seeded SKUs**, all us-east-1 On-Demand (t3.micro, m5.large, c5.large, S3 Standard, Lambda requests) |
| Pricing | `get_products` for RDS / DynamoDB / ELB | `InvalidParameterException: Invalid ServiceCode` |
| Cost Explorer | `get_cost_and_usage` | Supported, but **every amount is $0.00** |
| Cost Explorer | `get_dimension_values` | Supported (36 services) |
| Cost Explorer | `get_tags` | Supported, no data |
| Cost Explorer | `get_cost_forecast` | **Unsupported** (`UnknownOperationException`) |

Because of this, the platform uses Floci data first and falls back to clearly labelled
reference or simulated data.

## Data sources and labelling

Every table carries a `source` / `price_source` column, and every page shows a coloured badge:

| Label | Meaning |
|-------|---------|
| `floci_api` | Actual response from the Floci API |
| `reference_assumption` | Documented reference price (`data/reference/`), **not** retrieved from an API |
| `region_derived` | us-east-1 price × documented region multiplier |
| `simulated` | Generated synthetic billing record. **Not actual AWS expenditure** |
| `user_defined` | Hypothetical configuration entered in the Infrastructure Builder |

### Sample datasets

| File | Description |
|------|-------------|
| `data/reference/ec2_instances.csv` | EC2 specs and On-Demand / Reserved / Spot prices for ~860 instance types (course EC2 dataset) |
| `data/reference/reference_prices.yaml` | Hand-documented us-east-1 list prices for S3, EBS, EFS, Lambda, DynamoDB, RDS, ElastiCache, ELB, CloudFront, Route 53, SQS, SNS, ECS, EKS, Athena, Glue, Backup and CloudWatch |
| `data/synthetic_billing.csv` | 12 months of **simulated** daily billing records (see below) |
| `data/scenarios/*.json` | Saved infrastructure scenarios (three examples included) |

### Synthetic billing dataset (Module 2)

Generated by `finops.billing.generate_synthetic_billing(seed=42)`, which is deterministic.

- Five departments from the project scenario, each using its listed services
  (Development: EC2/S3; E-commerce: EC2/RDS/S3/ELB; Analytics: EC2/S3/Athena;
  Customer Services: Lambda/DynamoDB/S3; IT Operations: CloudWatch/Backup).
- Tag columns: `department`, `project`, `environment`, `account_id`.
- Regions: us-east-1, eu-west-1, us-west-2.
- Monthly growth per service (storage +4.5%/mo, backup +6%/mo, others 2–3.5%/mo), weekday
  patterns, ±6% daily noise, and three injected cost spikes.
- Calibrated so the last full month is about **$5,600**, above the $5,000 budget in the
  final-demo scenario.

Regenerate it from the Cost Explorer sidebar or with
`python -c "from finops.billing import load_synthetic_billing as l; l(regenerate=True)"`.

## Cost calculation assumptions

All constants are in `finops/assumptions.py`. Each estimate page also shows them in an
*Assumptions and exclusions* panel.

| Item | Assumption |
|------|-----------|
| Hours per month | 730 (8,760 / 12) |
| Days per month | 30.42 |
| Annual cost | monthly × 12 |
| Base region | us-east-1. Other regions use multipliers (eu-west-1 ×1.07, eu-central-1 ×1.15, ca-central-1 ×1.10, ap-southeast-1 ×1.20) |
| EC2 Reserved 1yr | From `ec2_instances.csv` where present, else 36% discount |
| EC2 Reserved 3yr All Upfront | 60% discount; upfront = effective rate × 26,280 h |
| Compute Savings Plan | 1yr 28%, 3yr 50% discount |
| Spot | Minimum observed spot price from the dataset, else 70% discount |
| RDS | Multi-AZ = ×2 instance and storage; Reserved 1yr = 35% discount; PostgreSQL priced as MySQL |
| Lambda | Requests + GB-seconds, no free tier |
| Commitments | Billed for all 730 h/month, whatever the utilisation |
| **Excluded** | Data transfer, free tier, taxes, credits, support plans, and any requests not entered |

An estimate is not an AWS bill.
